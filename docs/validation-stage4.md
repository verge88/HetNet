# Этап 4: КИЕ, независимые свидетельства и сбои транспорта

**Цель:** отделять подозрение на подделку отчёта узла от повреждения
контрольного сообщения в пути и обычной недоступности наблюдения.

Научная основа — приложенная диссертация: глава 2 (контрольные
информационные единицы), §3.3.3–3.4.6 (узлы, зоны, независимый транзитный
учёт, инварианты), §3.8 и §4.1 (проверка воспроизводимости). В
диссертации рассмотрено более широкое семейство КИЕ-признаков
(задержка, джиттер, потери, целостность, контекст зоны). HetNet
реализует **подмножество**, не воспроизводит все признаки и модели
диссертации. КИЕ не является стандартизованным сетевым wire-протоколом
3GPP или ITU-T.

## 1. Наблюдение КИЕ

Шесть контролируемых узлов: msc2, sgsn3, mme4, dra, pcscf, amf5.
Период опроса по умолчанию — 1500 мс. Отдельный имитационный
контрольный канал использует два перехода (запрос/ответ), каждый с
независимой вероятностью потери, установленной в scenario.loss_rate.
Это **допущение**, а не измеренная маршрутизация оператора.

На каждом интервале формируется CU.Reconciliation со следующими
независимо интерпретируемыми признаками:

- cu_delivered: был ли реально получен имитационный ответ;
- mac_valid: прошёл ли HMAC-SHA256 по узлу, nonce и счётчикам;
- observer_consistent: совпадает ли **весь вектор операций** с
  независимым транзитным счётчиком; равных сумм недостаточно;
- reported_total, observed_total и counter_disagreement;
- cu_consecutive_losses и cu_staleness_ms — потери и устаревание.

Если ответ потерян, MAC и числа отчёта равны null: сравнение
не проводится и узел не обвиняется. Если часть ответов потеряна,
но доставленные отчёты согласованы, вывод consistent_with_loss.

HMAC-ключи модели детерминированно выводятся из seed, **это не
криптографическая защита работающего оператора**. Отдельная
независимость наблюдателя только моделируется.

## 2. Классы свидетельств

| Классификация | Признаки | Значение |
|---|---|---|
| persistent_report_divergence | два последовательных доставленных отчёта с корректным MAC, но рассогласованных с внешним учётом | подозрение на подделку отчёта или ошибку наблюдателя; не доказательство взлома |
| report_integrity_failure | неверный MAC доставленного КИЕ | повреждение/изменение в пути; нельзя автоматически приписывать узлу |
| unconfirmed_divergence | единичная подтверждённая рассогласованность | наблюдений недостаточно |
| consistent_with_loss | хотя бы один ответ потерян, остальные доставленные отчёты согласованы | транспорт ухудшился, по полученным отчётам рассогласований нет |
| telemetry_degraded | отсутствуют пригодные контрольные ответы | невозможно оценить отчётность |
| consistent | достоверно доставленные отчёты согласованы | нет выявленных отклонений |
| insufficient_evidence | сравнимые данные отсутствуют | решение не принимается |

Анализатор работает только с CU-событиями, **не** читает метки attack,
внутренние множества атакующих узлов или список тревог.
Сохранена возможность проверить его на внешних допустимых
измерениях при появлении независимого эталона.

## 3. Изолированные сценарии

Scenario.node_case:
- none — контроль без вмешательства;
- report — DRA подписывает заведомо ложные счётчики своим ключом;
- tamper — в пути к MSC меняются данные без пересчёта MAC;
- both — оба случая одновременно;
- auto — при включённых синтетических атаках оба, иначе none.

Точки инъекции в симуляции: 72% и 74% временного горизонта.
При запуске node-study другие синтетические MAP/Diameter/SIP атаки
выключены, чтобы не смешивать узловой и сигнальный ground truth.

## 4. Повторяемый запуск

    python -m pip install -e .
    python -m unittest discover -s tests -v

    python -m hetnet run --duration 18 --subscribers 8 --no-attacks --node-case report --output results/report-only
    python -m hetnet run --duration 18 --subscribers 8 --no-attacks --node-case tamper --output results/tamper-only

    python -m hetnet node-study --duration 18 --subscribers 8 --start-seed 42 --runs 6 --loss-rates 0,0.1,0.35 --output results/node-study

В result.json и node_evidence.json сохраняются выводы,
в node_study.json — матрица проверок по узлам: истинные метки
**из настроек эксперимента**, предсказанные категории,
TP/FP/FN/TN, полнота, точность и доля доставленных КИЕ.

Оценка разбита на два независимых класса: (1) обнаружение
подделки **подписанного** отчёта и (2) обнаружение изменения
контрольного сообщения в пути. Они не сводятся к общей точности
без оговорок.

## 5. Границы метода

Это новый **исследовательский симулятор**, не 3GPP conformance или
межоператорский interoperability-test. Не реализованы реальное
SCTP/TLS/SS7/HTTP/2 взаимодействие КИЕ, ротация ключей, конкурирующие
наблюдатели, зоны с независимым консенсусом, таймеры и причинность
радиоподсистем. Подделанный отчёт с корректным MAC не устанавливает,
почему независимый учёт расходится. Продолжение требует оценки
корректности самого наблюдателя и устойчивости к согласованному
отказу нескольких датчиков.
