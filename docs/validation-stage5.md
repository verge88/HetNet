# Этап 5. Три независимых наблюдателя, кворум и сбои доверия

**Область:** имитационная оценка того, насколько правдоподобно утверждать о подделке отчёта сигнального узла, когда сам независимый наблюдатель может ошибаться или быть скомпрометирован.

Источники постановки задачи: предоставленная диссертация, глава 2 (КИЕ), §3.3.3–3.4.6 (события узла/зоны, независимый транзитный учёт), §3.8 и §4.1 (синтетическая верификация). Реализация трёх наблюдателей — **новая исследовательская гипотеза HetNet**, а не готовый механизм из диссертации. КИЕ не является стандартизованным протоколом 3GPP/ITU-T.

## Архитектура

Для каждого логического контролируемого узла создаются три наблюдателя в разных **имитационных административных доменах**:

| Наблюдатель | Домен доверия | Данные |
|---|---|---|
| `tap-legacy` | `legacy-probe-domain` | Отдельно подписанный вектор наблюдаемых операций |
| `tap-epc` | `epc-probe-domain` | Такой же вектор, отдельный ключ |
| `tap-5gc` | `5gc-probe-domain` | Такой же вектор, отдельный ключ |

Это **не** физическое распределение датчиков по операторским площадкам. Для каждого опроса вектор счётчиков подписывается HMAC-SHA256, привязывается к узлу, идентификатору наблюдателя, времени и nonce. Проверяются срок давности (по умолчанию 1000 мс), подпись, уникальность наблюдателя и подлинность принадлежности к заявленному домену.

Кворум = не менее **двух из трёх** корректных подписанных голосов, совпадающих по полному вектору операций. Дубликаты идентификатора не добавляют голос; MAC-ошибка, старый nonce, неверный домен или устаревшая подпись исключают голос. При отсутствии большинства статус `split` либо `insufficient`, а проверяемая истинность отчёта узла остаётся **неопределённой**.

КИЕ (подписанный отчёт контролируемого узла) и голоса наблюдателей проверяются раздельно. `src/hetnet/control.py` использует именно **верифицированный кворум**; при наличии кворума сравнивает весь вектор `reported_counts` с `consensus_counts` вместо единственного итогового числа. При запуске из симулятора анализатор получает имитационный корневой ключ и **повторно проверяет исходные подписи голосов**, игнорируя редактируемое поле `observer_quorum` в JSON. Если вызвать анализатор без корневого ключа, он принимает уже рассчитанный результат как *недоверенную сводку*; внешнюю подлинность такое использование **не подтверждает**. Два последовательных подтверждённых несовпадения могут дать класс `persistent_report_divergence`, но **не доказывают компрометацию**. При пропущенных голосах и старых успешных подтверждениях нельзя гарантировать корректность последнего отчёта.

## Сценарии отказов

В `Scenario.observer_case` (отдельно от `node_case`):

| Сценарий | Что моделируется в узле DRA после 72% горизонта |
|---|---|
| `none` | Все наблюдатели правильно считают операции |
| `one_faulty` | Один датчик подписывает ложные данные; два остальных независимы |
| `two_colluding` | Два датчика подписывают один ложный вектор: большинство вводит детектор в заблуждение |
| `outage` | Два наблюдателя не предоставляют голоса |
| `mixed` | Один подписывает ложный вектор, другой недоступен; большинства нет |
| `bad_mac` | Один голос изменён без повторной подписи, исключается |
| `stale` | Один голос имеет устаревшую временную метку, исключается |

`observer_loss_rate` независимо добавляет случайные потери голосов всех наблюдателей. Потери КИЕ по `loss_rate` — **другая** модель и отдельно задаваемая вероятность. В реальных сетях эти события могут быть коррелированы; здесь их независимость — явно оговорённое допущение.

**Известный предел достоверности:** два сговорившихся датчика могут создать ложный кворум для честного отчётного узла или скрыть согласованную подделку отчёта. Криптографическая подпись сама по себе не гарантирует правдивость показаний.

## Воспроизводимый запуск

```bash
python -m pip install -e .
python -m unittest discover -s tests -v

# Без вмешательства в узел, один ложный датчик
python -m hetnet run --duration 18 --subscribers 8 --no-attacks \
  --node-case none --observer-case one_faulty \
  --output results/stage5/single

# Скомпрометированное большинство наблюдателей
python -m hetnet run --duration 18 --subscribers 8 --no-attacks \
  --node-case report --observer-case two_colluding \
  --output results/stage5/collusion

# Матрица: 6 seed, потери 0/20/45%, семь режимов
python -m hetnet zone-study --duration 18 --subscribers 8 \
  --start-seed 42 --runs 6 --observer-loss-rates 0,0.2,0.45 \
  --output results/stage5/study
```

В `result.json` и `events.csv` сохранены голоса и результаты кворума; `node_evidence.json` содержит классификацию, доступность независимого кворума, список несогласных датчиков и отклонённых голосов; `zone_study.json` включает раздельные TP/FP/FN/TN по сценариям и вероятность потери.

**Метрика:** истинная подделка только в сценарии `node_case=report`, детектор получает только КИЕ и подтверждённые голоса, не получает метку сценария. Считается качество обнаружения *подделки отчёта узла*, а не вероятность обнаружения компрометированного наблюдателя: отдельный голос меньшинства — свидетельство расхождения, а не однозначная атрибуция виновного.

## Границы применимости

Это модель **2-of-3 fault assumption**, не Byzantine Fault Tolerance при произвольном противнике и не эксплуатационный multi-party consensus. Она не гарантирует корректность при двух ошибочных наблюдателях, общих неисправностях, общей компрометации ключей или атаке на каналы доверия. Имитационные HMAC-ключи детерминированы seed, реальные источники данных, безопасность аппаратных ключей и транспорт отсутствуют.

Точное соответствие протоколов мобильных сетей по TS Release 18 в рамках этой части не утверждается: стандартный 3GPP КИЕ-формат отсутствует. Для дальнейшего научного подтверждения потребуются проверка топологии наблюдения, независимых доверенных источников и физическое сопоставление с допустимыми обезличенными трассами.
