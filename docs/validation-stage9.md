# Этап 9 — раздельное обучение и сравнение зональных детекторов

## Назначение

Реализовано контролируемое сравнение трёх исследовательских
правил выявления поддельных отчётов контролируемых узлов:
существующего подписанного CU baseline,
порога на нормированный избыточный остаток КИЕ
(zone_absolute) и порога на отклонение от медианы
других узлов в той же зоне (zone_peer).

**Это синтетическая лабораторная валидация.**
Реальные операторские данные, физически независимые
датчики и внешне размеченные атаки отсутствуют.
Локальные агрегаты этапа 8 без attack labels **не
смешиваются** с синтетической разметкой этого этапа.
Source ID обозначает сценарный профиль, не независимую
площадку. Новое правило зонального обнаружения
не является обученным ML-детектором или полным
воспроизведением моделей диссертации.

## Обучение

На чистых симуляциях без подделанных отчётов и
общих сбоев датчиков фиксируются максимальные
попарные значения нормированного зонального остатка
и отклонения от leave-one-out медианы, плюс эпсилон
1e-12. Порог выбирается **только на чистых**
тренировочных запусках, без доступа к меткам
тестовых атак. Глобальный максимум — описательный
консервативный порог наблюдённой нормы, не
теоретическая гарантия FPR.

Профили train:
- synthetic_fit_nominal: 0% пропусков событий;
- synthetic_fit_capture: 5% пропусков;
- оба с допуском 1 событие, seed 21–24.

## Проверка

Четыре группы heldout:
- synthetic_holdout_nominal: 0% пропусков, нормальное наблюдение;
- synthetic_holdout_shift: 15% пропусков, нормальное наблюдение;
- synthetic_holdout_outage: 5% пропусков и общий отказ EPC+5GC;
- synthetic_holdout_collusion: 0% пропусков, подписанное ложное большинство EPC+5GC.

Каждая группа проверяется на seed 42–45,
по трём когортам: без подделки,
подделка отчётов MSC 2G+AMF 5G,
подделка отчётов MME 4G+P-CSCF IMS.

Всего 48 симуляций, 288 узловых примеров
на каждый детектор. Тестовые и обучающие
source_id и seed не пересекаются; это техническая
проверка отсутствия **идентичного ID**, но
не проверка физической независимости.

Подделка отчёта в сценарии возникает после 72%
модельного горизонта. По заранее зафиксированному
правилу оценка проводится в последней четверти
горизонта (с 75%) на **двух подряд подтверждённых**
контрольных периодах с шагом 1500 мс.
Ограничение на априори известный период атаки
исключает прямое распространение выводов
на реальные неизвестные моменты вмешательства.

Входом детекторов являются только
проверенные CU-отчёты и зональные признаки.
Истинная разметка берётся из настроек инъекции
только **после решения** для расчёта метрик.
Все методы используют одну и ту же исследовательскую
семью подписанных КИЕ, то есть не являются
независимыми комплексами защиты.

## Нехватка свидетельств и метрики

Если нет двух подряд проверенных наблюдений
с корректной подписью узла и кворумом наблюдателей,
детектор делает **abstention** — отказывается
от вывода. Для zone_peer нужна также медиана
других проверенных узлов.

Основные TP/FP/FN/TN, precision/recall/FPR/F1
вычисляются **только на примерах, по которым
принято решение** (selective metrics).
Если отсутствуют необходимые знаменатели,
соответствующая доля равна null, а не нулю.

Отдельно выводятся:
- общее число узловых примеров, число решений
  и доля покрытия (coverage);
- отказ от вывода для атакованных и честных узлов;
- консервативная полнота
  recall_with_abstentions_as_misses, в которой
  все невыявленные атакованные узлы включены
  в знаменатель, включая abstentions;
- разрез по источнику/детектору и
  описательная средняя/дисперсия по seed.

При общем отказе двух датчиков отсутствие ложных
тревог при нулевом покрытии **не** означает
хорошего качества детектора. При сговоре
двух подписывающих датчиков может возникнуть
ложное большинство, скрывающее подделанные
отчёты и обвиняющее честные узлы.

Из-за коррелированных синтетических сценариев
и повторения виртуальных узлов доверительные
интервалы и выводы о статистической
значимости не заявляются.

## Воспроизводимый запуск

    python -m pip install -e .
    python -m unittest discover -s tests -v

    python -m hetnet zonal-compare \
      --duration 18 --subscribers 8 \
      --train-start-seed 21 --train-runs 4 \
      --test-start-seed 42 --test-runs 4 \
      --output results/stage9/heldout

Итоговый JSON: results/stage9/heldout/zonal_comparison.json.
В GitHub Actions отдельно сохраняется
hetnet-stage9-source-heldout-detectors.
Файл содержит thresholds, source profiles,
узловые решения и сводные таблицы;
реальные операторские строки не используются.

## Научные ограничения

Не реализованы реальные operator-heldout
security labels, независимые подписанные
физические источники, поиск неизвестного
момента атаки, обученный ML, промышленное
криптографическое управление ключами,
сертификационная 3GPP Release 18 conformance
или wire-level interoperabilty GSM/UMTS/LTE/NR.
