# Этап 6 — несколько узлов 2G–5G и общие отказы зон наблюдения

**Область:** исследовательское развитие HetNet. Это имитационная модель
сигнального control plane и КИЕ, а **не** реализация реальных пакетов
MAP/TCAP, Diameter, SIP, GTPv2-C, SBI и не подтверждение conformance
по ITU-T/3GPP/IETF.

## Основание и отличие от диссертации

Приложенная диссертация, §3.3.3, определяет событие уровня узла как
агрегат состояния и подтверждённый отчёт КИЕ, а событие уровня
зоны — через *медианы, ранги и дисперсии* по зоне контроля. В §3.4.4
описаны относительные отклонения узлов и z-оценки, в §3.4.5 —
признаки КИЕ (доставка, целостность, потери, устаревание и др.).

**В этой версии HetNet реализована другая, дополнительная
экспериментальная ось:** признаки **одновременного отсутствия**
или несогласия свидетельств от общей административной зоны
для нескольких узлов на одном интервале. Это не воспроизведение
полного семейства зональных z-признаков или ML-моделей
из диссертации и не копирование её экспериментальных метрик.
Проверка охватывает несколько поколений, но не реальные
радиоинтерфейсы или протоколы сетевого взаимодействия.

## Множество узлов и детектор

Контролируемые логические узлы:
msc2 (2G), sgsn3 (3G), mme4 и dra (4G), pcscf (IMS),
amf5 (5G). Истинные метки вмешательства задаются отдельно
как tuple report_fault_nodes. Каждый выбранный узел после
72% временного горизонта выдаёт **корректно HMAC-подписанный
ложный отчёт**: к вектору операций добавляется fabricated +5.
Выбор узла **не** передаётся детектору.

Для каждого цикла КИЕ все три логических наблюдателя
tap-legacy, tap-epc, tap-5gc подтверждают векторы операций.
Проверяющий пересчитывает их HMAC с имитационным ключом, проверяет
nonce, время, адресата и совпадение показаний минимум 2/3
наблюдателей. Сохранённый результат observer_quorum
не является доверенным исходным вводом. Положительный
класс контроля узла — persistent_report_divergence:
два подряд проверенных противоречия с большинством.

## Синхронные общие отказы

Параметры:

- shared_zone_case = none: нет общего отказа;
- epc_outage: недоступен tap-epc, два других датчика ещё могут
  образовать кворум;
- epc_5gc_outage: одновременно недоступны tap-epc и tap-5gc,
  кворум отсутствует;
- epc_corrupt: tap-epc подписывает ложный счётчик,
  два остальных представляют неповреждённый базовый вектор;
- epc_5gc_collude: tap-epc и tap-5gc совместно подписывают
  одинаковый ложный вектор, то есть **ложное большинство**;
- all_outage: нет ни одного голоса.

shared_zone_probability (0…1) — вероятность активации
**всей описанной группы зон за один период**, а не
отдельная вероятность на узел. Общий исход
вычисляется один раз для периода КИЕ и действует одновременно
на всех шести узлах. Отдельные observer_loss_rate и loss_rate
(голоса датчиков и канал КИЕ) остаются независимыми
от нового общего процесса. Активация общего воздействия
начинается после 72% времени моделирования. RNG фиксируется seed;
порядок обхода узлов не меняет общие отказы.

## Межузловой слой корреляции

domain_analysis.analyze_domain_correlations проверяет сырые
подписанные голоса по **каждому узлу и периоду**,
без входных attack labels и без доверия сохранённым
observer_quorum. Фиксируется:

- shared_missing — отсутствие **одного домена наблюдения**
  у двух или более разных контролируемых узлов в одном периоде;
- shared_invalid — множество ошибок подписи/свежести/домена
  для одного датчика на двух или более узлах;
- shared_outlier — один датчик расходится с кворумом
  при двух или более узлах;
- cross_node_quorum_loss — не менее двух узлов не имеют кворума;
- одновременно пропавшие домены и перечень затронутых
  логических поколений.

Повтор одного и того же узлового события не может
создать ложную корреляцию: подсчёт производится по
уникальному node ID. Выводы говорят о **совпадающих симптомах**,
а не об атрибуции злоумышленника. Два сговорившихся датчика
могут заставить честный датчик выглядеть отклоняющимся.

**Критическое допущение:** все виртуальные датчики
получают из симулятора **один общий базовый транзитный вектор**.
Они логически разделены ключами и каналами, но **не являются
тремя физически независимыми источниками**. Полученные
результаты не подтверждают эмпирическую независимость
средств мониторинга.

## Запуск

    python -m pip install -e .
    python -m unittest discover -s tests -v

    # Узлы 2G+5G с ложными отчётами, общий отказ двух датчиков
    python -m hetnet run --duration 18 --subscribers 8 --no-attacks \
      --node-case none --report-fault-nodes msc2,amf5 \
      --shared-zone-case epc_5gc_outage --output results/stage6/demo

    # Детерминированное исследование сразу нескольких поколений:
    python -m hetnet cohort-study --duration 18 --subscribers 8 \
      --start-seed 42 --runs 6 \
      --fault-cases none,epc_outage,epc_5gc_outage,epc_corrupt,epc_5gc_collude \
      --cohorts none,legacy_5g,epc_ims \
      --shared-zone-probability 1 \
      --output results/stage6/cohorts

    python -m hetnet serve

Группы узлов: none — все честны; legacy_5g — msc2+amf5;
epc_ims — mme4+pcscf; four_generations —
msc2+sgsn3+mme4+amf5 (доступна в CLI).
При 6 seed, 5 режимах и 3 группах — **90 прогонов**.
Второе значение seed повторяемо, но это не независимая
производственная выборка.

Экспорт: result.json, node_evidence.json,
domain_evidence.json, events.csv, observations.csv;
в режиме cohort-study — cohort_study.json.
Оценка TP/FP/FN/TN ведётся на уровне узлов,
дополнительно сохраняется разрез по поколениям
и счетчики эпох отсутствующего общего кворума.

## Критерии проверки и ограничения

- Честные узлы при массовом отсутствии кворума не должны
  маркироваться как компрометированные **только из-за потерь**.
- Сохранённый кворум при отказе одного домена может обнаружить
  подделку нескольких узлов разных поколений.
- Два сговорившихся домена способны обвинять честные узлы
  и скрывать подделку отчёта, несмотря на валидные MAC.
- Корреляция общих ошибок не даёт автоматической
  идентификации виновного наблюдателя.
- Единые периоды, общие ключевые предположения и модель
  подписанного счётчика — синтетические; нет независимых
  операторских capture, общих причин сбоев в реальных
  физических зонах или доверенных физических timestamp.
- Нет новых тестов сертификационного соответствия 3GPP Release 18
  или реализации стандартного 5G SBA/NAS/NGAP wire transport.
