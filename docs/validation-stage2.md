# Этап 2: модели процедур, трафика, очередей и проверка экспериментов

**Статус:** программно реализованная исследовательская абстракция, а не стек сетевых протоколов и не 3GPP conformance testing.

## Источники и отделение новых допущений

Из приложенной диссертации использована **форма методики**, изложенная в §§ 3.2–3.8, 4.1: фиксированные интервалы наблюдения, суточные колебания нагрузки, AR(1), задержки/потери в звеньях, КИЕ, повторные прогоны с seed 42–51, оценка по типам сигнализации. По таблице 3.2 у исходных автономных моделей интервалы составляют **30 с (ОКС-7), 15 с (Diameter), 20 с (SIP/IMS)**; по таблице 4.1 исходные 24-часовые наборы имели по 51 840, 86 400 и 47 520 записей. В HetNet эти числа *не воспроизводятся автоматически*: у проекта иная объединённая топология и новый порядок событий. Для GTPv2-C и 5G SBI введены собственные иллюстративные интервалы 15 и 10 с — **их нет** в указанной таблице диссертации.

Реализованная генерация задаёт базовые интенсивности для пяти доменов (в запросах/сек), суточный профиль
`1 + A cos(2π × (t/3600 − peakHour)/24)`, AR(1) процесс
`x[t] = φ × x[t−1] + σ × ε[t]`, где `ε` — стандартное нормальное отклонение, а число событий на секунду имеет распределение Пуассона с `λ = baseRate × scale × max(0.05, daily + AR1)`. Значения baseRate и параметры AR1 — **калибровка демонстратора**, а не измеренные значения сети оператора.

## Состояния и транзакции

- Логическая последовательность 2G/3G: `MAP.SendAuthenticationInfo → MAP.UpdateLocation/UpdateGprsLocation → успешный ReturnResult`.
- 4G: `Diameter AIR/AIA → ULR/ULA → GTPv2-C CreateSessionRequest/Response`.
- 5G: `NRF Discovery → AUSF authentication → UDM registration → SMF context creation`; цепочка проверяет ответ AUSF и ответ UDM.
- IMS: успешный `REGISTER/200` перед `INVITE`, предварительные `100/180`, `200(INVITE)`, `ACK`, `BYE/200`.
- `ProcedureLedger` сопоставляет идентификатор корреляции, псевдоабонента, обратные адреса и ожидаемый ответ. Повторение открытой операции, неверная последовательность и ответ без запроса регистрируются как нарушение; состояние регистрации меняется **после** сопоставленного положительного ответа.
- Тайм-аут модели 2000 мс по умолчанию; отслеживаются просроченные транзакции. Реальные сетевые таймеры и процедуры отказа могут отличаться, поэтому проверка ограничена этим подмножеством.

## Звенья и наблюдения

Модель применяет к каждому **ориентированному** направлению звена последовательное обслуживание, сериализацию PDU и буфер очереди. STP-звенья получают иллюстративные 64/128 кбит/с, остальные — 100 Мбит/с. PDU имеют **оценочные**, не стандартизованные размеры: MAP 140 Б, Diameter 320 Б, GTPv2-C 180 Б, SIP 520 Б, SBA 600 Б. При превышении буфера событие обозначается `CONGESTED`; независимая вероятность потери проверяется на каждом переходе; итоговые задержки учитывают каждый hop.

Выходной файл `observations.csv` агрегирует события по стеку, исходному узлу и окну: счётчики исходов, операции, доли атак, медианную и p95 задержку. Подробности доступны в `events.csv` и `result.json`.

## Эксперимент и область достоверности

```bash
python -m pip install -e .
python -m unittest discover -s tests -v
python -m hetnet run --duration 60 --subscribers 16 --traffic-scale 3 --output results/run
python -m hetnet experiment --duration 18 --subscribers 8 --start-seed 42 --runs 10 --output results/experiment
```

`experiment.json` и `experiment_runs.csv` содержат TP, FP, FN, TN, precision, recall, F1 и FPR **на уровне корреляций синтетических сообщений**, раздельно по протокольным стекам; представлены среднее и выборочное стандартное отклонение по 10 seed. Истина берётся из меток генератора, а детекторы не получают их в качестве входа. Контроль КИЕ/компрометации узлов в оценку message-level не включён: для него нужен отдельный датасет состояний и верификация.

Это **не** репликация заявленных в диссертации AUC/F1 и не повторение её 24-часовых обучающих выборок. В этой версии нет обучения ML, AUC, доверительных интервалов и теста Уилкоксона; при отсутствии сопоставимых детекторов он не имеет смысла. Оценки качества нельзя переносить на действующие операторские сети.

## Фиксация релиза и прослеживаемость

`standards/release18.json` содержит **конкретные** известные редакции TS Release 18 и ссылки на официальные ETSI work items/публикации; ссылки RFC указывают нормативные документы IETF. Тесты проверяют внутренние инварианты указанной упрощённой модели, **не** протокольное или сертификационное соответствие 3GPP. Сертификационная задача потребует ETSI TTCN-3, трасс реальных пакетов, кодеков, безопасного транспорта, QoS и реального interworking.

## Ограничения безопасности

Синтетические сигнальные атаки выполняются исключительно внутри дискретно-событийной программы, без подключения к реальным ядрам, STP, MME или gNB. Чувствительные абонентские идентификаторы не генерируются.
