# HetNet — результаты этапа 11: эпизоды с неизвестным началом

Исследование выполнено на **трёх специально созданных синтетических**
тестовых источниках, а не на операторских измерениях. Это не
подтверждение соответствия 3GPP/ITU-T или качества обнаружения
на сетевых трассах.

## Протокол эксперимента

Код: модуль \`src/hetnet/temporal_episodes.py\`.
Тестирование выполнено в GitHub Actions:
[CI run #44385489478](https://github.com/verge88/HetNet/actions/runs/44385489478).
В этом прогоне пройдён **181** unittest на Python 3.10/3.12,
успешно выполнены \`episode-audit\`, \`episode-eval\` и экспорт JSON.

В дальнейшем добавлен специальный тест для полностью
пропущенного контрольного интервала; новая реализация
учитывает такие интервалы в **знаменателе покрытия**.
Для трёх демонстрационных файлов, где все относительные интервалы
0–11 присутствуют, результаты следующей таблицы не меняются.

Обучение: только чистые синтетические Stage 10 источники
lab_clean_alpha, lab_clean_beta; подделок и временных эпизодов
в них нет. Порог по нормированному абсолютному отклонению
и peer-медиане соответствует максимуму подтверждённой
тренировочной нормы + 1e-12. В обучении **не** использованы
проверочные эпизоды или источники.

Проверка: 3 источника по 12 относительных интервалов
и 6 логических узлов, всего **216 агрегированных
узло-интервалов**, размечено **6 атакующих эпизодов**.
Тестовые сценарии:

- alpha: атаки разной длительности на msc2 (2G)
  и amf5 (5G);
- beta: двухинтервальная атака mme4 (4G),
  одноинтервальная атака pcscf (IMS) и общее
  нормальное смещение счётчиков;
- gamma: более продолжительные атаки amf5 (5G)
  и sgsn3 (3G), в том числе с исчезновением
  контрольных свидетельств.

Эти эпизоды НЕ поступают детектору: он получает
только счётчики по относительным интервалам и
заранее закреплённые пороги. Сопоставление
возникающих тревог с разметкой производится после
завершения причинного сканирования. Для успешного
обнаружения требуются **две подряд** подтверждённые
точки **внутри** полуоткрытого эпизода [start,end).

## Фактические метрики по всем трём источникам

| Показатель | CU claimed baseline | Zone absolute | Zone peer |
|---|---:|---:|---:|
| Размеченных эпизодов | 6 | 6 | 6 |
| Обнаруженных эпизодов | 3 | 3 | 3 |
| Пропущенных эпизодов | 3 | 3 | 3 |
| Episode recall | 50% | 50% | 50% |
| Всего тревог | 10 | 10 | 7 |
| Сопоставленных тревог | 3 | 3 | 3 |
| Несопоставленных тревог | 7 | 7 | 4 |
| False alerts вне полноценных эпизодов | 7 | 7 | 4 |
| Precision тревог | 30% | 30% | 42,86% |
| Средняя задержка обнаруженных эпизодов | 1 интервал | 1 интервал | 1 интервал |
| Доля доступных пар узловых наблюдений | 89,39% | 89,39% | 89,39% |
| Доступных подтверждающих пар внутри атак | 9/15 | 9/15 | 9/15 |
| Заведомо слишком короткие эпизоды | 1 | 1 | 1 |

Эти значения получены при **одном фиксированном**
маленьком синтетическом наборе и сконструированных
законах искажения, поэтому их нельзя трактовать
как операторскую статистику, доверительные
интервалы или независимый security benchmark.

Алгоритм Zone Peer снизил число несопоставленных
тревог при таком характере синтетического общего
смещения, не изменив полноту распознавания
эпизодов или доступность контрольных данных.

Задержка «1 интервал» не означает 1 с, 1500 мс
или какую-либо известную latency реальной сети.
Атака, продолжающаяся один интервал, **не может**
дать две внутренние подтверждённые точки по
выбранному правилу и честно записана как
пропущенная. Аналогично, если подтверждения
пропали, наличие подделки в truth-разметке
не даёт права детектору считать её обнаруженной.

## Научные ограничения

1. **Источник истины** — сконструированная синтетическая
   интервальная разметка. Внешних подтверждённых
   экспертных аннотаций и операторских трасс нет.
2. Никакие настоящие HMAC-подписи внешних КИЕ
   в этой схеме не представлены: \`cu_verified_claim\`
   и \`quorum_verified_claim\` являются только
   утверждениями автора файла. Метод baseline
   поэтому назван \`cu_claimed_baseline\`.
3. Формальные source_id, lineage_id, SHA-256
   проверяют лишь очевидные дубликаты; физической
   независимости датчиков эти проверки не гарантируют.
4. Повторяющиеся атакующие случаи и общие искажения
   не обеспечивают независимой статистической
   выборки. Без разрешённых внешних наборов
   с качественной экспертизой нельзя заявлять
   доверительные интервалы, выбор оптимального
   порога или результаты обобщения.
5. Нет полнофункционального wire-level теста
   3GPP Release 18, MAP/TCAP, Diameter, SIP, GTP,
   5G SBI/HTTP2 или радио GSM/UMTS/LTE/NR.
6. Реальный неконтролируемый onset/offset,
   истинные временные метки, случайные clock drift
   и причинная связь сетевой атаки с отклонениями
   здесь отсутствуют.

## Воспроизводимость

    python -m pip install -e .
    python -m unittest discover -s tests -v

    python -m hetnet episode-eval \
      --train examples/labeled/lab_clean_alpha.json \
              examples/labeled/lab_clean_beta.json \
      --holdout examples/episodic/episodic_holdout_alpha.json \
                examples/episodic/episodic_holdout_beta.json \
                examples/episodic/episodic_holdout_gamma.json \
      --output results/stage11/episodes

Полная методика:
[docs/validation-stage11.md](validation-stage11.md).
Экспорт \`episode_comparison.json\` содержит только
параметры обучения, агрегированные результаты и
отпечатки измерений, но **не** исходные агрегаты
и **не** покадровую truth-разметку.
