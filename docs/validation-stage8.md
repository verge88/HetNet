# Этап 8 HetNet — локальные агрегаты и оценка с разделением источников

## Назначение и границы

Добавлен локальный интерфейс для импорта агрегированных счётчиков
наблюдателей. Истинных внешних операторских данных в репозиторий
не загружали. Исследование выполнено на трёх **явно синтетических**
файлах. Разные source_id позволяют технически исключить пересечение
обучающего и тестового источника по идентификатору, но **не
гарантируют** независимость физических измерителей или эталонов.

Приложенная диссертация использовалась в предыдущих этапах как
постановка для контроля КИЕ и узловых/зональных признаков.
Этот новый импорт, взвешенная калибровка и разделение источников —
самостоятельная инженерная методика, не воспроизведение
её ML-экспериментов и численных результатов. КИЕ не является
стандартным форматом 3GPP/ITU-T.

## Строгая минимизированная схема JSON

Размер файла ограничен 1 МиБ, максимум 20 000 строк.
Корневые ключи, без дополнительных полей:
schema_version=1, source_id, provenance, reference_basis, measurements.

source_id должен быть неприватным псевдонимом из ASCII с шаблоном
букв/цифр/подчёркивания/тире, от 3 до 48 символов, начинается
со строчной латинской буквы.

Для provenance=synthetic требуется reference_basis=synthetic_truth.
Для provenance=supplied_aggregate требуется
reference_basis=claimed_independent_aggregate. Слово claimed
означает исключительно декларацию владельца файла, а не
проверенное независимое измерение.

Каждая строка measurements содержит ровно шесть полей:

| Поле | Значение |
|---|---|
| observer | tap-legacy, tap-epc, tap-5gc |
| node | msc2, sgsn3, mme4, dra, pcscf, amf5 |
| operation_class | MAP, Diameter, GTPv2-C, SIP, SBI |
| interval_index | Только относительный целочисленный номер интервала |
| reference_count | Целое от 20 до 1 000 000 |
| observed_count | Целое от 0 до reference_count |

Дубли комбинации интервал/узел/класс/наблюдатель запрещены.
Поля IMSI, SUPI, MSISDN, телефон, IP, payload, абонентский ID,
абсолютное время, сырые сообщения или другие дополнительные
поля не принимаются. Повторные ключи JSON, нечисловые значения,
булевы значения вместо чисел и нечисловые специальные
NaN/Infinity отклоняются.

Порог reference_count >=20 уменьшает риск экспорта
единичных наблюдений, но **не означает двадцать уникальных
абонентов, k-анонимность или доказательство обезличивания**.
Для реального использования организация должна отдельно
проверить правомерность экспорта, состав групп, секретность,
правила хранения и отсутствие идентифицирующей информации.
Никогда не публикуйте реальные агрегаты в открытый репозиторий
или CI-артефакт без явного разрешения.

## Калибровка и честное разделение источников

Три синтетические фикстуры находятся в examples/external:
lab_training_alpha, lab_training_beta и lab_holdout_gamma.
Первая пара используется только для обучения, третья —
для теста. Присутствие тестового source_id в обучающих
немедленно вызывает ошибку. Тренировочные источники обязаны
совместно содержать все три домена наблюдения.

Для каждого observer строится взвешенная по числу
референтных событий оценка доли пропусков:

    p_hat = sum(reference_count - observed_count) / sum(reference_count)

При оценке на holdout прогнозируется **наблюдаемое**
количество событий по известному reference_count:

    predicted_observed = reference_count * (1 - p_hat)

Далее измеряются средние абсолютные ошибки и смещение:
- MAE откалиброванной модели;
- MAE наивной модели без пропусков, в которой прогноз равен эталону;
- средняя ошибка прогноза со знаком;
- число полностью измеренных комбинаций интервал/узел/класс
  с тремя разными observer;
- средняя и медианная ширина разброса относительных долей
  наблюдения для полностью измеренных комбинаций.

**Важное ограничение:** reference_count тестового источника
является входным числом для прогноза observed_count. Это
проверка пригодности тренировочной оценки потерь при смене
источника, **не** прогноз полного объёма событий без эталона.
Поля observed_count теста не используются для обучения.

В этом импорте нет меток атак, компрометации, подделки КИЕ
или доверенных внешних truth labels; следовательно
здесь **не определены** TP, FP, FPR, precision, recall,
F1 или ROC-AUC как показатели кибербезопасности.
Нельзя смешивать MAE калибровки с обнаружением атак.

## Воспроизводимые команды

    python -m pip install -e .
    python -m unittest discover -s tests -v

    # Проверка схемы и безопасный краткий аудит
    python -m hetnet aggregate-audit \
      --input examples/external/lab_training_alpha.json

    # Обучение на двух синтетических источниках и проверка на третьем
    python -m hetnet external-eval \
      --train examples/external/lab_training_alpha.json \
              examples/external/lab_training_beta.json \
      --holdout examples/external/lab_holdout_gamma.json \
      --output results/stage8/external

Артефакт external_eval.json включает только параметры модели,
сводные показатели, count объектов и SHA-256 fingerprint
канонизированных агрегатов; исходные ряды в результаты
не помещаются. Fingerprint позволяет сопоставить версии
входа, **но не** подтверждает происхождение или подпись
источника. Наличие source_id или файловой контрольной суммы
не доказывает физическую независимость наблюдений.

Все операции локальные: нет подключения к оператору,
захвата пакетов, работы с IMSI/SUPI или автоматической
отправки файлов в сеть.

## Ограничения и дальнейшее развитие

- Режим оценивает только недоучёт, observed_count<=reference_count;
  переучёт, дублирование и ложные события требуют отдельной схемы.
- Отдельное название источника может соответствовать тому же
  физическому датчику: source-disjoint не эквивалентно site-disjoint.
- На реальные данные нужны разрешённые выгрузки по независимым
  устройствам и общий стандартизованный протокол учёта событий.
- Нет внешней лабораторной калибровки, независимого эталона
  или проверки разрешённого юридического происхождения.
- Зональные признаки этапа 7 пока описательные; их
  security-оценка на разрешённых размеченных данных — следующая задача.
- Никакой новый 3GPP Release 18 conformance, SS7/TCAP,
  Diameter, SIP, GTPv2-C или реальный 5G SBI interop
  в этом этапе не заявляется.
