# Этап 7 HetNet — зональная статистика КИЕ и погрешности наблюдателей

## Научная постановка и границы

В приложенной диссертации (§3.3.3) событие уровня зоны определяется как агрегат узлов с медианами, рангами и дисперсиями отклонений; §3.4.4 описывает относительные отклонения от медианы, z-оценки и ранги; §3.4.5 содержит более обширную группу признаков КИЕ (доставка, задержки, целостность, потери, устаревание, согласованность). На этом этапе HetNet создаёт *собственное ограниченное подмножество описательных признаков* на нормированных остатках КИЕ. Это **не** полная реализация диссертационного ML и не воспроизведение её численных результатов.

КИЕ и виртуальные зональные подписи не являются wire-протоколами 3GPP/ITU-T. Не заявляется conformance или interoperabilty с операторскими сетями.

## 1. Виртуальное наблюдение с независимо семплированными ошибками

До этапа 7 три логических наблюдателя использовали один и тот же синтетический транзитный счётчик без отдельных ошибок захвата. Теперь параметр observer_capture_miss (0…0.5) моделирует пропуск отдельного события каждым виртуальным наблюдателем. Псевдослучайная последовательность независима по (node, observer, epoch, operation) и воспроизводится из seed. Для n≤400 событий применяется биномиальная выборка, для n>400 — нормальная аппроксимация потерь с ограничением результата в допустимых границах.

**Независимыми здесь являются ошибки наблюдателей условно на одном общем источнике синтетических событий, но НЕ физические источники данных.** Нет действительного разнесения измерителей по площадкам, внешних трасс и операторских синхронизаторов.

## 2. Ограниченный кворум 2 из 3

Параметр quorum_max_count_delta задаёт допустимое абсолютное различие по **каждой операции** в signed witness vectors. Значение 0 по умолчанию означает исходное строгое равенство словарей из этапов 1–6 (включая состав ключей операций). Положительный допуск допускает пару согласованных показаний, если покомпонентная разница не превышает порог. При конкурирующих попарно согласованных максимальных кворумах система возвращает ambiguous, не выбирает произвольную пару.

Пример: 10/11/30 при допуске 2 даёт однозначную пару 10/11; 0/2/4 создаёт две конкурирующие пары и приводит к неопределённости. Принятый вектор — покомпонентная медиана голосов, округлённая до целого. Подписанный отчёт контролируемого узла также считается согласованным, только если покомпонентная разница с этим вектором не превышает допуск. Слишком большой допуск может скрыть реальное искажение.

Свидетельства перепроверяются в детекторе: HMAC наблюдателя привязан к идентичности, домену, времени, узлу и nonce. Дополнительно выполняется **повторная проверка HMAC самого отчёта КИЕ** по контрольному лабораторному ключу, не доверяя сохранённым в JSON признакам mac_valid или observer_quorum. При вызове старого API без проверочного ключа допускается только более слабый режим доверия к заранее рассчитанной сводке.

Ключи выводятся из seed и существуют только для воспроизводимой лабораторной симуляции; это не production-grade PKI.

## 3. Описательные признаки зоны

Наблюдаемые логические узлы: msc2 (2G), sgsn3 (3G), mme4/dra (4G), pcscf (IMS) и amf5 (5G). На каждом контрольном интервале включаются только узлы с доставленной КИЕ, верной подписью отчёта и криптографически проверенным кворумом 2/3. Недоставленные, неподтверждённые и дублирующиеся события исключаются, **не подставляются нулём**.

Для вектора счётчиков по операциям вычисляется excess_discrepancy — сумма max(0, abs(reported[k]-consensus[k])-tolerance). Её нормированная величина excess_ratio = excess_discrepancy / max(1, sum(consensus.values())) используется для сравнения разных поколений. Объёмы сообщений разных ролей не считаются непосредственно сопоставимыми.

На векторе excess_ratio проверенных узлов периода рассчитываются:
- медиана и среднее, population std, median absolute deviation (MAD);
- разность узлового значения с медианой всей зоны;
- разность с медианой **других** проверенных узлов (leave-one-out);
- обычная z-оценка и устойчивая оценка 0.6745*(x-median)/MAD;
- ранг по убыванию excess_ratio с общим рангом для равных значений.

При нулевой дисперсии обычная z-оценка 0; при MAD=0 и ненулевом отклонении robust z=NULL (не бесконечность). Для статистики коллег требуется минимум три проверенных узла в зоне. Экспортируются размеры и доля пригодных наблюдений, чтобы отсутствие измерений не маскировалось под норму.

**Признаки описательные**, а не обученный детектор и не доказательство компрометации. В probe-study метрики TP/FP/FN/TN по-прежнему относятся к правилам CU persistent_report_divergence, а не к классификатору по зональным рангам.

## 4. Воспроизводимые команды

    python -m pip install -e .
    python -m unittest discover -s tests -v

    # 2G+5G, самостоятельные ошибки измерения и допуск 2 события
    python -m hetnet run --duration 18 --subscribers 8 \
      --no-attacks --node-case none --report-fault-nodes msc2,amf5 \
      --observer-capture-miss 0.05 --quorum-max-count-delta 2 \
      --output results/stage7/demo

    # Чувствительность 6 seed x 3 уровня пропуска x 3 допуска x 2 группы
    python -m hetnet probe-study --duration 18 --subscribers 8 \
      --start-seed 42 --runs 6 \
      --capture-miss-rates 0,0.05,0.15 \
      --tolerances 0,1,2 --cohorts none,legacy_5g \
      --output results/stage7/probe-study

    python -m hetnet serve

Результаты включают zonal_evidence.json, node_evidence.json, domain_evidence.json, result.json и probe_study.json. Полная матрица — **108 прогонов** (6 seed × 3 miss × 3 tolerance × 2 cohorts); в каждой настройке 72 узловых примера, из них 12 подделанных и 60 честных.

## 5. Ограничения

- Закон ошибок захвата виртуальных датчиков синтетический и не калиброван на независимых операторских измерениях.
- Все датчики используют один общий имитационный транзитный счётчик. Физическая независимость не проверена.
- При сговоре двух наблюдателей 2/3 кворум можно обмануть независимо от достоверности подписи.
- Зональная статистика не заменяет причинную модель, безопасную атрибуцию или разрешённую экспертную разметку.
- Для реальной научной валидации нужны независимые обезличенные трассы, обучение/тестирование без утечки источника, контроль смещения и оценки неопределённости. Реальная 3GPP conformance и interop не выполнены.
