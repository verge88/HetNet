# Этап 8 — результаты source-disjoint агрегатной калибровки

Дата: 18 ноября 2026 г.

**Источник измеренных чисел:** GitHub Actions
https://github.com/verge88/HetNet/actions/runs/44350801370
(первый полный прогон 123 unit tests на Python 3.10 и 3.12).
Последующий повторный прогон с двумя дополнительными
негативными тестами JSON/типов
https://github.com/verge88/HetNet/actions/runs/44351237891
выполнен успешно: **125 тестов**.
Экспортируется артефакт hetnet-stage8-aggregate-holdout
с результатом external_eval.json.

Все исходные наборы в examples/external являются
**синтетическими**. Это проверка алгоритма и формата,
а не реальных независимых операторских измерений.

## Методика

Два обучающих источника:
- lab_training_alpha, 36 агрегированных записей;
- lab_training_beta, 36 агрегированных записей.

Отдельный проверочный источник:
- lab_holdout_gamma, 36 агрегированных записей,
  3 наблюдателя, 3 контролируемых узла,
  2 относительных временных интервала.

В каждом тестовом окне (relative interval, node, operation class)
есть все три наблюдателя: **12 полных окон из 12**.

Оценка пропусков по наблюдателю
p_hat = sum(reference_count - observed_count) / sum(reference_count)
вычисляется **только** на 72 обучающих строках.
На тесте прогнозируется observed_count по известному
reference_count и тренировочному p_hat.
Контрольный baseline просто предполагает отсутствие
пропусков (predicted_observed=reference_count).

## Числа, полученные в CI

| Наблюдатель | Число тестовых строк | MAE без калибровки | MAE с калибровкой | Signed bias модели |
|---|---:|---:|---:|---:|
| tap-legacy | 12 | 23,167 | 4,778 | +4,778 |
| tap-epc | 12 | 33,000 | 8,116 | +8,116 |
| tap-5gc | 12 | 46,333 | 11,660 | +11,660 |
| **Все** | **36** | **34,167** | **8,184** | **+8,184** |

Средний разброс относительной доли захвата по трём
наблюдателям в полностью заполненных тестовых окнах:
0,06993; медиана 0,06814.

Систематическое положительное смещение означает, что
прогноз ожидаемого наблюдаемого объёма **выше**
фактического, так как в синтетическом holdout задан
более высокий уровень пропусков, чем в тренировочных
источниках. Падение MAE относительно наивной модели
показывает только полезность тренировочного базового
профиля относительно предположения «нет пропусков».
Оно **не** означает независимую физическую проверку,
успешное обнаружение атак, производственную точность
или оптимальную оценку вероятности ошибок реальных датчиков.

## Проверенные свойства

- Только одобренные coarse поля с агрегированными
  счётчиками, без личных ID и payload; лишние
  поля отклоняются;
- minimum reference_count 20, ограничение размера
  1 МиБ и числа записей;
- JSON с повторными именами полей, NaN/Infinity,
  неправильными типами, маленькими счётчиками,
  повторными интервалами/датчиками отклоняется;
- совпадение source_id между train и holdout
  приводит к ошибке до записи результата;
- обучение требует данных всех трёх наблюдателей;
- выходной отчёт не содержит исходные measurements,
  только агрегированные параметры, статистику
  и хеши воспроизводимости;
- CLI aggregate-audit / external-eval успешно выполняются
  на Python 3.12, полный unittest на 3.10/3.12.

## Чего эти результаты не подтверждают

Для этих файлов **нет attack labels**, поэтому метрики
обнаружения (TP/FP/FN/TN, precision, recall, FPR,
ROC-AUC, PR-AUC) **не определены**. Несовпадение имени
source_id не гарантирует независимость физического
сигнального канала или отдельность эталона.
Реальные трассы не были загружены, а provenance
входного файла не проверяется криптографически.
Порог 20 событий не доказывает k-анонимность.

Это не испытание соответствия 2G–5G стандартам
ITU-T/3GPP/IETF и не воспроизведение
результатов диссертации. Следующая самостоятельная
задача — получение *разрешённых обезличенных*
независимых агрегатов, подтверждение происхождения
каждого reference_count, проверка пересечений
временных интервалов и введение независимых
аннотаций событий безопасности.

Методика и формат: docs/validation-stage8.md.
